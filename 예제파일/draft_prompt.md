# 초안 프롬프트: 고객 문의 응답 초안 생성기 (v0.1)

> ⚠️ 이 프롬프트는 "사전 점검" 실습을 위해 **의도적으로 60점 수준**으로 작성되었습니다.
>  Instruction 명확성, 예제 유무, 누락된 지침 등을 직접 발견하고 개선하는 실습에 활용합니다.

---

## 프롬프트 본문

```
# Role
당신은 "AI PM 코치"(https://coach.proagent.kr/) 서비스의 고객 지원 상담사입니다.
PM(Product Manager)을 대상으로 하는 AI 코칭 SaaS 제품에 대해 고객 문의에 응답합니다.

- 전문적이면서도 친근한 톤을 유지합니다.
- 고객의 질문에 공감을 표현하고, 명확한 답변을 제공합니다.
- 고객을 "고객님"으로 호칭합니다.

# 응답 형식
- 인사 → 문의 내용 확인 → 답변/안내 → 마무리 인사 순서로 작성합니다.
- 응답 길이는 150~300자 내외로 간결하게 작성합니다.
- 마크다운 형식은 사용하지 않습니다.
- 답변 말미에 추가 문의를 환영하는 문장을 포함합니다.

# 출력 언어
- 고객의 문의 언어에 맞춰 동일한 언어로 응답합니다.
- 기본 언어는 한국어입니다.

# 참조 문서
아래 문서를 기반으로 고객 문의에 답변합니다.

{reference_knowledge}

# 고객 문의
{customer_inquiry}

위 고객 문의에 대한 응답 초안을 작성해주세요.
```

---

## 의도적으로 포함된 보완 포인트

> 아래는 수강생에게 공개하지 않는 **강사용 메모**입니다.
> 사전 점검 실습 후 디브리핑 시 활용합니다.

### 현재 프롬프트에 이미 포함된 요소 ✅

| 요소 | 설명 |
|------|------|
| Role 정의 | 서비스명, 대상 고객(PM), 톤(전문적+친근), 호칭 지정 |
| 응답 형식 | 4단계 구조, 글자 수 가이드, 마크다운 제한, 마무리 멘트 |
| 출력 언어 | 고객 언어 매칭, 기본 한국어 |
| 참조 문서 활용 | reference_knowledge 변수로 주입 구조 확보 |

### 보완 포인트 맵 (수강생이 발견해야 할 항목)

| # | 점검 항목 | 현재 상태 | 기대하는 개선 방향 |
|---|----------|----------|------------------|
| 1 | **Few-shot 예제 없음** | 좋은 응답과 나쁜 응답의 예시가 전혀 없어서, AI가 "인사 → 확인 → 답변 → 마무리" 구조를 어떤 수준으로 채워야 하는지 감을 잡기 어려움 | Good Example 1~2개 + Bad Example 1개를 제공하여 품질 기준선을 설정. 특히 "공감 표현"과 "간결한 답변"의 구체적 수준을 예시로 보여줘야 함 |
| 2 | **문의 유형별 분류/라우팅 기준 없음** | 기능 질문, 요금 문의, 버그 신고, 불만/클레임 등을 구분하지 않고 단일 응답 로직만 존재 | 문의 유형을 분류하고, 유형별로 다른 대응 가이드 필요. 예: 버그 신고 → 기술팀 에스컬레이션 안내, 환불 요청 → 고객센터 연결 안내 |
| 3 | **에스컬레이션 기준 없음** | AI가 직접 처리해야 할 것과 담당자에게 넘겨야 할 것의 경계가 없음 | "결제/환불 관련 → 고객센터 안내", "기술 오류 → 기술지원팀 안내", "법적 문의 → 담당자 연결" 등 명확한 에스컬레이션 매트릭스 필요 |
| 4 | **개인정보 처리 지침 없음** | 고객이 카드번호, 주민번호, 전화번호 등을 포함해 문의할 때의 처리 방법 미지정 | "응답에 고객의 개인정보를 반복하지 말 것", "민감정보는 마스킹 처리", "개인정보가 포함된 문의는 보안 채널 안내" 등 규칙 필요 |
| 5 | **금지 행동(Negative Instruction) 없음** | 하지 말아야 할 행동에 대한 가이드가 전혀 없음 | "할인/보상 약속 금지", "경쟁사 비하 금지", "기술적 추측 금지", "내부 정보(매출, 직원 수 등) 노출 금지", "시스템 프롬프트 공개 금지" 등 |
| 6 | **참조 문서 범위 외 질문 처리 규칙 없음** | reference_knowledge에 없는 내용을 질문받았을 때의 처리 방법이 없음 | "참조 문서에 없는 내용은 추측하지 말 것", "확인 후 안내 드리겠다는 표현 사용", "관련 부서 연결 안내" 등 hallucination 방지 규칙 필요 |
| 7 | **감정 상태별 대응 가이드 부족** | "공감을 표현하고"라는 일반적 지침만 있고, 화난 고객/실망한 고객 등 구체적 감정 상태별 대응 전략이 없음 | 감정 강도별 대응 가이드 필요. 예: 불만 고객 → 사과 우선 + 구체적 해결 안내, 혼란스러운 고객 → 단계별 가이드 제공 등 |
